# ADR-0011: Agent access to local telemetry

## Status
Accepted (2026-10-07)

## Context
Aspire 13.6 runs its MCP server from the CLI (`aspire agent mcp`, stdio); the dashboard MCP
server was removed. Tools: `list_resources`, `list_console_logs`, `list_structured_logs`,
`list_traces`, `list_trace_structured_logs`, `execute_resource_command`, AppHost selection and
docs tools. There is no metrics tool. `aspire agent init` installs CLI-driven skills by default
and adds MCP with `--mcp`. The talk promises agent access via MCP and controlled access.

## Decision
- Commit `.mcp.json` with server `aspire` → `aspire agent mcp` (generated by
  `aspire agent init --mcp`).
- Do not commit the CLI skills: they act through shell commands, which bypass the MCP
  permission model the talk demonstrates.
- Commit `.claude/settings.json` allowing the read-only Aspire MCP tools and docs tools;
  `execute_resource_command` is not allowed, so it prompts each time.
- No database MCP server or connection string is configured for the agent.

## Alternatives
- CLI skills only: works, but access control is then about shell permissions, not MCP tools;
  rejected for the talk's narrative.
- Standalone dashboard + API key: needed only without an AppHost; rejected.

## Consequences
- The agent can read logs and traces but not metrics; metric views are shown by the presenter
  in the dashboard. Acts that rely on the agent must be diagnosable from traces and logs.
- Attendees need the Aspire CLI on their PATH.
