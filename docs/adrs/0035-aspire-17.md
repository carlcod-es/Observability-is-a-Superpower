# ADR-0035: Aspire 17

## Status
Accepted (2026-11-24, PO). Supersedes the Aspire version in ADR-0001.

## Context
Aspire 17.0.0 shipped on 2026-11-17. It supports .NET 10 or later. It deprecates `Aspire.AppHost.Sdk`
(warning ASPIRE012) and `AddProject<TProject>` (CS0618) in favour of `Microsoft.NET.Sdk` with
`Aspire.Hosting.AppHost` + `Aspire.Hosting.Dotnet` and `AddDotnetProject(name, path)`; both still
work. The PO asked to upgrade Umbraco to 19 on .NET 11, but Umbraco 19 is only at 19.0.0-rc2.
The PO decided (2026-11-24) to stay on the Umbraco 17 LTS and .NET 10, and in the first round to make
only the Aspire upgrades that are required.

## Decision
- Aspire 17.0.0: `Aspire.AppHost.Sdk/17.0.0` and all `Aspire.*` packages;
  `CommunityToolkit.Aspire.Hosting.OpenTelemetryCollector` 17.0.0 (it needs Aspire.Hosting 17).
  Aspire CLI 17.0.0.
- Keep `Aspire.AppHost.Sdk` and `AddProject<TProject>` for now (deprecated, not removed); migrating them
  is a recorded follow-up (FR-0007).
- Everything else is unchanged: .NET 10, Umbraco 17, OpenTelemetry, Microsoft.Extensions, container images.

## Alternatives
- Umbraco 19 RC on .NET 11: prerelease CMS for the demo; rejected by the PO.
- Full upgrade in one go (AppHost migration, library and image bumps): more to verify at once;
  deferred by the PO.
- Stay on Aspire 13.6: misses the supported line; rejected.

## Consequences
- The build shows ASPIRE012 and two CS0618 warnings until the AppHost is migrated.
- Aspire 17 default images: Redis 8.10, RabbitMQ 4.4. The persistent `oisp-cache` and `oisp-queue`
  containers are recreated once; the Redis volume keeps the booking counts.
- The redesigned Aspire dashboard may change presenter steps (resource Rebuild, logs and traces views).
- The dashboard MCP server is removed in Aspire 17. The opt-in `aspire agent mcp` setup is unchanged; the
  CLI MCP has 15 tools (new: `get_integration_docs`) and still no metrics.
- Attendees need the Aspire CLI 17.0 or later.
- Verified 2026-11-24: build has no errors; 75/75 tests; `aspire start` brings every resource up healthy;
  smoke check passes pages, forms, emails, traces, dashboards and labels; a booking message is counted by
  the api and reaches Grafana (`acme_bookings_counted_total`). The smoke's booking checks fail because all
  events are in the past (follow-up).
